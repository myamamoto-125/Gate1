# 社内問い合わせ管理 — ステータス変更・担当者割り当て

Python 3.9以上 / SQLite。外部パッケージ不要。要件定義書 v1.2 の詳細画面、状態遷移、担当者割り当て、履歴、サーバー側権限チェック、楽観的排他制御を実装。

## 起動

```sh
python3 server.py --demo
```

http://127.0.0.1:8080 を開きます。サンプルデータの管理者キーは `admin-demo`、一般担当者キーは `member-demo`。本番の秘密情報ではありません。データは `inquiries.sqlite3` に保存されます。デモはループバック接続のみ受け付けます。

```sh
python3 -m unittest discover -s tests -v
```

## 既存システムとの統合

登録と一覧は既存機能の想定のため、確認用の最小一覧とサンプル投入を用意しました。登録機能は追加していません。`domain.change` が独立した更新サービスです。既存ログインから得たユーザーIDを渡してください。クライアント送信のユーザーIDやroleは認証に使いません。

単体実行時はログインキーをサーバー環境変数 `INQUIRY_LOGIN_KEYS`（例: キーをプロパティ、users.idを値とするJSON）から設定し、`--demo`なしで起動します。ユーザーは既存DB側で管理してください。DBパスは `INQUIRY_DB` で指定できます。実運用では既存の社内認証との連携・HTTPSリバースプロキシ・`COOKIE_SECURE=1` を設定します。付属HTTPサーバーとメモリーセッションはローカル検証用です。

## 仕様の扱い

- ステータス変更は全有効メンバーに許可（仕様に担当者本人限定の制約なし）。担当者変更の制約はサーバーで検証。
- 未対応から対応中への自動割り当てでは、画面例に従い担当者履歴とステータス履歴を各1件保存。
- 任意コメントはUnicodeコードポイントで200文字以内を検証。保存カラムが定義されていないため永続化しない。
- 同一担当者への変更は画面で無効化。直接API呼び出しでは権限エラーとして拒否し、履歴は増やさない。
- 未割り当てに戻すR-05違反には既定の権限エラーを使用。
- 担当者変更でも updated_at を更新。マイクロ秒精度で単調増加させ、同時更新の取りこぼしを防止。
- SQLiteのINTEGER PRIMARY KEYは64ビット整数。VARCHARの長さとENUM相当の制約をスキーマで設定。日時はUTC保存・日本時間表示。
- 氏名の五十音順は漢字の読みがDBに定義されていないため、`static/name-readings.json` の読み辞書を参照。未知の氏名は日本語照合順にフォールバック。既存ユーザー全員の読みを辞書に登録することで正確な五十音順になる。

## 保証する更新単位

`BEGIN IMMEDIATE` 内で認証対象の有効フラグ、updated_at一致、業務ルールを確認し、本体更新と全履歴をコミット。履歴挿入失敗時は全体をロールバック。履歴は時刻降順・同時刻ではID降順、最大20件。

## 構成

- `schema.sql`: 指定3テーブルと履歴参照用インデックス
- `domain.py`: 業務ルール・トランザクション
- `server.py`: ローカル確認用HTTP API、セッション認証、CSRF対策
- `static/`: 日本語の詳細画面・確認用一覧
- `tests/`: 状態遷移16組み合わせ、権限、境界値、排他、ロールバック検証

セッションとDBの実データ、認証キーはGitに含めません。
